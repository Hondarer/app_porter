# 基盤 (base) 機能仕様

## 概要

基盤機能は、porter のすべての機能に共通する、結果の表し方と診断出力の入口を定めます。

利用側は、どの機能を呼び出した場合も同じ規則で成否を判定できます。  
また、サービスを開く前から診断出力を有効にして、開始処理を含む動作を追跡できます。

## 解決する課題

通信の失敗要因は、引数の誤り、資源の不足、相手の不在、タイムアウトなど多岐にわたります。  
機能ごとに異なる成否の表し方を用いると、利用側は機能ごとに判定方法を個別に把握する必要があります。

porter は下位の通信を別の層を通じて利用します。  
下位の層が返す値をそのまま利用側へ渡すと、利用側は porter の外側の結果体系まで把握することになります。

また、サービスの開始に失敗した場合、開始後にしか診断出力を有効にできなければ原因を追跡できません。

基盤機能は、結果の表し方を 1 つに統一し、診断出力をサービスの開始より前から利用できるようにします。

## 結果の表し方

すべての操作は、成功を表す 1 つの値か、原因を区別する失敗値のいずれかを返します。  
成功を表す値は 1 つだけであり、失敗値は原因ごとに区別できます。

利用側は、成功したかどうかを、成功を表す値との比較によって判定します。  
失敗の原因を区別する場合は、個々の失敗値との比較によって判定します。

失敗値の分類は、値の大小や範囲によるものではありません。  
値の範囲を前提とした判定は、将来の失敗値の追加によって成立しなくなります。

## 失敗の区分

失敗値は、利用側が取る対応の違いに応じて次の区分を持ちます。  
区分は要件ではなく、失敗値を読み解くための目安です。

| 区分 | 内容 | 利用側が取る対応の例 |
|---|---|---|
| 引数と状態 | 引数の誤り、対応していない要求、対象が存在しない | 呼び出しを修正する |
| 資源と容量 | 記憶域の不足、受け付け容量の不足、保持範囲外 | 間隔をおいて再試行する |
| 通信 | 切断、タイムアウト、入出力の失敗、取り決めと異なる受信内容 | 通信の状態を確認する |
| 制御 | 処理の取り消し | 終了処理へ進む |
| 分類不能 | 上記のいずれにも分類できない失敗 | 診断出力を確認する |

## 結果値の範囲

porter は、下位の層が返した値をそのまま利用側へ返しません。  
下位の層で生じた失敗は、porter が定める失敗値へ対応付けたうえで返します。

これにより、利用側が把握する結果体系は porter が定める集合だけになります。  
対応付けられない失敗は、分類不能な失敗として返します。

## 診断出力の有効化

診断出力の入口は、サービスを開く前から利用できます。  
これにより、構成の読み取りや通信の開始に失敗した場合も、その過程を追跡できます。

診断出力は、利用側が有効にするまで行われません。  
出力先と重大度の下限は、この入口を通じて利用側が指定します。

## 診断出力の内容

出力する行には、時刻、重大度、出力位置、本文を含めます。  
重大度は、致命的な失敗から詳細な追跡までを区別できる段階を持ちます。

利用側が指定した重大度の下限に満たない行は出力されません。  
重大度の下限を低く設定するほど、出力の量が増えます。

## 適用範囲外

- 利用側アプリケーションのログ基盤との統合、および出力先の転送
- 失敗値からの利用側向け表示文言の生成
- 診断出力の保存期間、世代管理、収集
- 利用側による診断出力の書式定義
- 失敗値に対する再試行の可否の判定

## 前提と制約

利用側は、成功と失敗の判定を結果値の識別によって行います。  
値の大小や範囲を前提とした判定を行った場合、失敗値の追加によって判定が成立しなくなることがあります。

失敗値の区分は、失敗値を読み解くための目安です。  
区分に対する範囲比較で失敗を分類した場合、その判定は契約の対象外です。

診断出力は、通信の処理と同じプロセスで行われます。  
重大度の下限を低く設定した場合、出力の量が増えて通信の処理に影響することがあります。
