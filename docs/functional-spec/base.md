# 基盤 (base) 機能仕様

## 概要

基盤機能は、porter のすべての機能に共通する、結果の表し方と診断出力の入口を定めます。

利用側は、どの機能を呼び出した場合も同じ規則で成否を判定できます。  
また、サービスを開く前から診断出力を有効にして、開始処理を含む動作を追跡できます。

## 解決する課題

通信の失敗要因は、引数の誤り、資源の不足、相手の不在、タイムアウトなど多岐にわたります。  
機能ごとに異なる成否の表し方を用いると、利用側は機能ごとに判定方法を個別に把握する必要があります。

また、サービスの開始に失敗した場合、開始後にしか診断出力を有効にできなければ原因を追跡できません。

基盤機能は、結果の表し方を 1 つに統一し、診断出力をサービスの開始より前から利用できるようにします。

## 結果の表し方

すべての操作は、成功を表す 1 つの値か、原因を区別する失敗値のいずれかを返します。  
成功を表す値は 1 つだけであり、失敗値は原因ごとに区別できます。

利用側は、成功したかどうかを、成功を表す値との比較によって判定します。  
失敗の原因を区別する場合は、個々の失敗値との比較によって判定します。

失敗値の分類は、値の大小や範囲によるものではありません。  
値の範囲を前提とした判定は、将来の失敗値の追加によって成立しなくなります。

## 診断出力

診断出力は、サービスを開く前から有効にできます。  
これにより、構成の読み取りや通信の開始に失敗した場合も、その過程を追跡できます。

出力する行には、時刻、重大度、出力位置、本文を含めます。  
利用側は重大度の下限を指定でき、下限に満たない行は出力されません。

診断出力は、利用側が有効にしない限り行われません。

## 適用範囲外

- 利用側アプリケーションのログ基盤との統合、および出力先の転送
- 失敗値からの利用側向け表示文言の生成
- 診断出力の保存期間、世代管理、収集

## 前提と制約

利用側は、成功と失敗の判定を結果値の識別によって行います。  
値の大小や範囲を前提とした判定を行った場合、失敗値の追加によって判定が成立しなくなることがあります。

診断出力は、通信の処理と同じプロセスで行われます。  
重大度の下限を低く設定した場合、出力の量が増えて通信の処理に影響することがあります。
