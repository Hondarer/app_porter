# セッション識別 (session) 機能仕様

## 概要

セッション識別機能は、送信側が通信を開始するたびに識別を付与し、受信側がどの通信に属するメッセージかを判定できるようにします。

これにより、送信側が再起動した場合も、受信側は以前の通信の状態を引き継ぎません。

## 解決する課題

順序の保証と再送は、通信ごとの受信状態に基づいて行われます。  
送信側が再起動して通番を初期化した場合、受信側が以前の状態を保持したままでは、正常なメッセージを欠落や重複と誤認します。

また、多対一の到達範囲では、複数の送信元を混同せずに区別する必要があります。

遅れて到達した古い通信のメッセージを受理すると、受信状態が過去の状態へ戻り、順序の保証が成り立ちません。

セッション識別機能は、通信の開始ごとに識別を付与し、受信状態の対応付けと切り替えの基準を定めます。

## 通信の開始の識別

送信側は、通信を開始するたびに識別を付与します。  
識別には、通信を開始した時点を表す情報を含め、受信側が新旧を判定できるようにします。

受信側は、受理したメッセージの識別を、受信中の通信の識別と照合します。  
一致する場合だけ、そのメッセージを順序の判定と再送の要求の対象にします。

## 新しい通信への切り替え

より新しい通信の開始を検出した場合、受信側はそれ以前の通信に属する受信状態を破棄します。  
破棄した後、新しい通信として受信を開始します。

切り替えの際、以前の通信で順序の復元待ちとなっていたメッセージは引き渡されません。  
新しい通信の受信は、その通信の最初のメッセージから始まります。

## 受理しないメッセージの扱い

受信中の通信より古い通信に属するメッセージは受理されません。  
遅れて到達した古いメッセージによって、受信状態が過去の状態へ戻ることはありません。

受理しないメッセージは、欠落としても重複としても扱われません。  
このため、再送の要求は発生せず、通信が切断として扱われることもありません。

## 送信元の識別

多対一の到達範囲では、送信元ごとに異なる識別子が利用側へ通知されます。  
利用側は、この識別子によって送信元を区別し、特定の送信元を指定して返信できます。

識別子と送信元の対応は、その送信元との通信が継続する間、維持されます。  
通信が終了した後の識別子は、別の送信元に割り当てられることがあります。

## 適用範囲外

- 通信の識別に基づく相手の認証
- 利用側アプリケーションへの通信識別の公開
- 複数の通信をまたいだ受信状態の引き継ぎ
- 送信元の識別子の永続化
- 送信元ごとに受け付ける通信数の制限

## 前提と制約

通信の開始の新旧は、送信側の実時刻に基づいて判定します。  
送信側の実時刻が巻き戻った場合、新しい通信が古いと判定され、受信側が切り替わらないことがあります。

送信側の実時刻が大きく進んだ場合、その通信は以降の通信より新しいと判定され続けます。  
通信する機器の実時刻は、運用によって同期されていることを前提とします。

利用側は、送信元の識別子を複数の通信をまたいで保持しません。  
通信が終了した後は、同じ識別子が別の送信元に割り当てられることがあります。
