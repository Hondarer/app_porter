# 構成 (config) 機能仕様

## 概要

構成機能は、サービスの定義を受け取る方法と、指定のない項目に適用する既定値を定めます。

利用側は、外部の構成からサービスを選択して開く方法と、組み立てた構成を直接渡す方法のいずれかを利用できます。  
いずれの方法でも、値の検査は通信を開始する前に行われます。

## 解決する課題

通信の設定項目は、相手の所在、到達範囲、監視の間隔、保持の範囲など多数にわたります。  
これらをすべて利用側のコードへ埋め込むと、配備先ごとの差異を変更するたびに再構築が必要になります。

一方で、設定を外部から読み取る手段しか持たない場合、利用側が実行時に組み立てた設定を利用できません。

また、値の誤りが通信の開始後に判明した場合、利用側は通信の失敗と構成の誤りを区別できません。

構成機能は、外部の定義から読み取る方法と、利用側が組み立てた定義を直接渡す方法の両方を提供し、値の検査を通信の開始前に行います。

## 構成の受け取り

構成は、外部の定義から読み取るか、利用側が組み立てた定義を直接渡すことで受け取ります。  
外部の定義から読み取る場合、利用側はサービスの識別子を指定して 1 つのサービスを選択します。

外部の定義に含まれるサービスの識別子は、利用側が列挙できます。  
これにより、利用側は構成に記載された内容を事前に把握してから、開くサービスを決定できます。

## 共通の設定とサービスごとの設定

1 つの構成には、複数のサービスの定義と、それらに共通する設定を配置できます。  
共通の設定は、個々のサービスの定義で上書きできます。

同じ項目が両方に記載されている場合は、サービスごとの設定が優先されます。  
どちらにも記載がない項目には、既定値が適用されます。

## 既定値

構成に指定されていない項目には、既定値が適用されます。  
これにより、利用側は変更が必要な項目だけを構成に記載できます。

既定値は、通信種別ごとの性質の違いを踏まえて定めます。  
監視の間隔とタイムアウトの判定には、データグラム型とストリーム型で異なる既定値が適用されます。

### 非負整数の入力

非負整数の設定項目へ文字列を指定する場合、負号付きの入力は、負のゼロも含め、専用の値 -1 を受け付ける項目に -1 を指定する場合を除き、構成が不正であることを返します。  
文字列を整数として解釈できない場合、型が異なる場合、およびその項目の整数表現の範囲を超える場合も、同様に構成が不正であることを返します。  
数値として指定された負のゼロは、ゼロとして扱います。

フロー制御と UDP の受信バッファーの設定のうち、専用の値を受け付ける項目は、この規則の例外です。  
これらの項目は、項目に応じて無効にする、または OS へ要求しないことを表す指定として -1 を受け付けます。

### 保持範囲の設定

再送と順序の復元に用いる保持範囲 (`window_size`) の既定値は 64 パケットです。  
設定できる範囲は 2 以上 256 以下です。

### フロー制御の設定

フロー制御の設定と UDP の受信バッファーの設定は、共通の設定 (`global`) とサービスごとの設定の両方で指定できます。  
サービスごとの設定で 0 を指定した場合と、項目を省略した場合は、共通の設定の値が使用されます。

共通の設定で容量に 0 を指定した場合は、容量による抑制を無効にします。  
サービスごとの設定で容量を無効にする場合は -1 を指定します。  
容量の既定値は無効であり、利用側が容量を構成しない限り、受信側は抑制を要求しません。

除外する台数と割合、猶予時間、通知量の予算、OS が保持できる量の見積もりに使う割合、および UDP の受信バッファーの大きさでは、共通の設定の 0 または省略は既定値の使用を表します。  
これらのうち専用の値 -1 を受け付ける項目では、共通の設定でもサービスごとの設定でも指定できます。

| 設定項目 | 既定値 | 意味 | -1 の意味 |
|---|---|---|---|
| `flow_control_excluded_receiver_count` | 1 | 除外する数の上限を決める台数 | 台数による上限の指定を無効にする |
| `flow_control_excluded_receiver_percent` | 10 | 除外する数の上限を決める割合 [%] | 割合による上限の指定を無効にする |
| `flow_control_grace_ms` | 200 | 遅い相手が全体の送出を止められる猶予時間 [ms] | 受け付けない |
| `flow_control_feedback_percent` | 5 | 監視対象から受けるフロー制御パケット数の予算。データ 100 パケットあたりの数 | 受け付けない |
| `flow_control_monitored_receiver_count` | 4 | 一対多の通信種別で監視する受信側の数の下限 [台] | サービスごとの下限の指定を無効にする |
| `flow_control_receive_buffer_percent` | 100 | OS が保持できる量に基づく受け入れられる範囲の見積もりに使う割合 [%] | OS が保持できる量に基づく範囲を無効にする |
| `udp_receive_buffer_size` | 4,194,304 | OS へ要求する UDP の受信バッファーの大きさ [バイト] | OS へ大きさを要求しない |

Table: フロー制御と UDP の受信バッファーの設定項目

除外する台数と割合の両方が有効な場合は、それぞれから定まる数の大きいほうを上限とし、活動中の受信側を少なくとも 1 台残します。  
両方を無効にした場合は、どの受信側も除外しません。  
多対一の UDP の待ち受け側でも、この上限と猶予時間を、他の相手への送信を妨げる相手の切断の判定に使います。

監視する受信側の数は、通知量の予算から自動で決まり、指定した下限を優先して、64 台と候補の数以下にします。  
監視する数の下限について、共通の設定の 0 は下限の指定なしを表し、サービスごとの設定で下限の指定を無効にする場合は -1 を使用します。  
抑制の要求と解除のしきい値、要求を繰り返す周期、要求の有効期限は、無効にできません。

再送を行わない通信種別は、フロー制御の設定を無視します。  
UDP の受信バッファーの大きさの要求は、UDP のすべての通信種別に適用し、TCP には適用しません。

### マルチキャスト送信 TTL の設定

`multicast` と `multicast_raw` では、送信時の到達範囲を定める TTL (`ttl`) を 1 から 255 の範囲で指定できます。  
設定ファイルで省略した場合および構造体で 0 を指定した場合は、実効値 1 を適用します。  
受信役では設定共有のため有効値を受け付けますが、ソケットへは設定しません。  
設定ファイルでの 0 や範囲外の指定、および `multicast`・`multicast_raw` 以外の種別への指定は、構成が不正であることを返します。

## 構成の検証

構成に定義されていない項目、解釈できない値、通信種別または認証方式に合わない項目、および許容範囲にない値がある場合、サービスは開かれません。  
サービスごとの項目には、通信種別および認証方式ごとに使用できる項目の組が定まっており、該当しない項目を記載した場合も構成が不正であることを返します (詳細な対応表は外部仕様に記載します)。  
検証は通信を開始する前に行われ、誤った構成のまま通信が始まることはありません。

構成に複数の誤りがある場合、構文の誤り、読み取りの失敗、メモリ不足を除き、検出したすべての誤りを利用側へ示します。  
また、サービスを開かずに外部の構成全体を検証する手段を備え、構成の誤りは利用側の呼び出し方の誤りと区別できる結果で返します。  
構成ファイルの読み取りに失敗した場合は、構成の誤りではなく、入出力の失敗として区別できる結果で返します。

指定された識別子のサービスが構成に存在しない場合も、サービスは開かれません。  
この場合は、ルートの構造と共通設定に誤りがなければ、構成の誤りではなく、対象が存在しないことを利用側へ返します。

## 互いに依存する設定

一部の設定は、単独では範囲内であっても、組み合わせとして成立しない場合があります。  
1 つのメッセージの大きさの上限を、一度に送出する大きさの上限より小さく設定した場合が、その例です。

フロー制御の設定では、次の組み合わせが成立しません。

- 解除するしきい値が、抑制を要求するしきい値以上である
- 要求の有効期限が、要求を繰り返す周期以下である
- 容量が、1 つのメッセージの大きさの上限より小さい
- 一対多の通信種別の受信側で容量を指定し、監視のための送出を無効にしている

次の値も、単独で許容される範囲にないものとして扱われます。

- 監視する受信側の数の下限が 64 を超える
- 除外する受信側の割合が、無効を表す指定でなく、100% を超える
- 通知量の予算が 1% から 100% の範囲にない
- 猶予時間が、待機時間に設定できる値の上限を超える
- OS が受信のために保持できる量に基づく範囲の、見積もりに使う割合が、無効を表す指定でなく、1% から 100% の範囲にない

このような組み合わせも通信の開始前に検出され、サービスは開かれません。  
利用側へは、構成が不正であることが返されます。

## 優先グループの構成

最大 8 経路のそれぞれに対して、優先グループ番号 (1 から 4) と、上位グループの回復を判定するまでの切り戻し待ち時間を構成できます。  
優先グループ番号を省略した場合の既定値は 1 であり、1 から 4 の範囲外の値を指定した場合は構成が不正であることを返します。

切り戻し待ち時間に 0 を指定した場合は、実効の切断判定時間と同じ値を用います。

## 証明書方式の構成

認証方式は、サービスごとに事前共有鍵方式 (既定) または証明書方式から選択します。  
証明書方式を選択した場合、次の条件のいずれかを満たさないときは構成が不正であることを返し、サービスを開きません。

- 自端の証明書と秘密鍵の両方が指定されており、読み込めること
- 信頼する CA の証明書または直接登録する相手の証明書の少なくとも一方が指定されており、読み込めること
- 信頼する CA の証明書を指定した場合、検証する相手の名前が 1 つ以上指定されていること
- 失効リストを指定した場合、そのファイルを読み込めること
- 片方向の通信種別で送信側として開く場合、自端の待ち受けポートが 0 以外に固定されていること

証明書、秘密鍵、および失効リストは、サービスを開く際に 1 回だけ読み込みます。  
更新を反映するには、サービスを閉じてから再度開きます。

## 通信種別の事前取得

利用側は、サービスを開く前に、そのサービスの通信種別だけを取得できます。  
この操作は通信を開始しません。

これにより、利用側は通信種別に応じて役割と通知先の要否を決定してから、サービスを開けます。

## 適用範囲外

- 構成の配布、配置、権限の管理
- 構成の変更の監視、および通信を継続したままの構成の再読み込み
- 利用側アプリケーションが必要とする、通信以外の設定項目
- 構成に記載された所在が実際に到達可能かどうかの事前確認
- 構成項目の推奨値の算出

## 前提と制約

構成の検証は、値が許容される範囲にあるかどうかと、設定の組み合わせが成立するかどうかを対象とします。  
対向側が実在するか、指定された所在に到達できるかは、通信を開始した後に判明します。

サービスを開いた後に構成を変更しても、継続中の通信には反映されません。  
変更を反映するには、サービスを閉じてから再度開きます。

通信する双方は、相互運用に関わる設定に同じ値を用います。  
異なる値を用いた場合、構成の検証は成功しても通信は成立しません。

## 選択の指針

構成の受け取り方は、設定が確定する時点に応じて選択します。

| 状況 | 受け取り方 |
|---|---|
| 配備先ごとに設定が異なり、再構築せずに変更したい | 外部の構成から読み取る |
| 設定が実行時に確定する、または利用側が算出する | 組み立てた定義を直接渡す |
| 構成に含まれるサービスを利用側に選択させたい | 識別子を列挙してから読み取る |
