# 通信保護 (security) 機能仕様

## 概要

通信保護機能は、事前に共有した鍵を用いて、メッセージの内容の秘匿と、改ざんの検出を行います。

保護の有効と無効は構成で選択します。  
保護を有効にした場合も、利用側の送信と受信の手順は変わりません。

## 解決する課題

通信の内容は、経路上で読み取られたり、書き換えられたりすることがあります。  
利用側が独自に暗号化を行うと、鍵の管理、改ざんの検出、形式の互換性の維持をそれぞれ実装することになります。

秘匿と改ざんの検出を別々に実装した場合、内容は読み取れなくても制御に関わる項目の書き換えを検出できないことがあります。

また、保護を有効にした構成へ保護されていないメッセージが到達した場合、これを受理すると保護は回避されます。

通信保護機能は、秘匿と改ざんの検出をあわせて担い、保護の有無を構成の選択に置き換えます。

## 保護の適用

構成で保護を有効にすると、メッセージの内容は暗号化されて送出されます。  
保護を有効にするかどうかはサービスごとに決定され、同じサービスの中で混在しません。

保護が有効な構成では、保護されていないメッセージは受理されません。  
これにより、保護を回避した通信が受理されることを防ぎます。

## 保護の範囲

秘匿の対象は、メッセージの内容です。  
送信元、宛先、大きさ、送信の時刻など、内容以外の情報は秘匿されません。

制御に関わる項目は、秘匿の対象ではありませんが、改ざん検出の対象です。  
このため、内容を読み取れない相手による項目の書き換えを検出できます。

## 改ざんの検出

受信したメッセージは、内容の復元とあわせて改ざんの有無が検証されます。  
検証に失敗したメッセージは破棄され、受信状態は変更されません。

破棄したメッセージは、欠落としても重複としても扱われません。  
このため、改ざんされたメッセージの到着によって再送の要求が発生することはありません。

## 鍵の指定

鍵は、構成で 2 つの方法のいずれかによって指定します。

| 指定の方法 | 内容 |
|---|---|
| 語句から導出する | 任意の長さの語句を指定し、porter が固定の方法で鍵を導出する |
| 値として指定する | 鍵の値をそのまま指定する |

語句から導出する場合、同じ語句からは常に同じ鍵が得られます。  
通信する双方が同じ語句または同じ値を用いることで、保護された通信が成立します。

## 適用範囲外

- 鍵の配布、保管、更新、および失効
- 通信の途中での鍵の切り替え
- 鍵が漏えいした場合における、過去の通信の秘匿性の維持
- 鍵の所持の確認を超える、通信相手の個体の認証
- 通信の相手、時刻、量など、内容以外の情報の秘匿
- 語句の強度の評価、および弱い語句の拒否
- 保護の失敗回数に基づく送信元の遮断

## 前提と制約

保護の強さは、利用側が指定した語句または値の強度に依存します。  
推測できる語句を指定した場合、保護は期待どおりの効果を持ちません。

鍵は構成から与えられ、通信の途中では変更されません。  
鍵が漏えいした場合、その鍵で保護した過去および将来の通信の秘匿性は維持されません。

保護は、通信の内容を対象とします。  
通信の相手、時刻、量は、保護を有効にした場合も観測できます。

保護の成立は、通信する双方が同じ鍵を用いていることを前提とします。  
一方だけが保護を有効にした場合、通信は成立しません。

鍵の所持は、通信相手の識別の根拠にはなりません。  
同じ鍵を持つ相手は、いずれも正当な相手として扱われます。

## 選択の指針

保護の要否は、経路の性質と、内容の秘匿の必要性に応じて選択します。

| 状況 | 保護の設定 |
|---|---|
| 経路が第三者から隔離されていない | 有効にする |
| 内容が第三者に読み取られてはならない | 有効にする |
| 送信元の偽装を排除する必要がある | 有効にする |
| 隔離された経路で、送出する量と処理時間を優先する | 無効にする |

送信元の限定だけでは、送信元を偽装した通信を排除できません。  
偽装の排除が必要な場合は、送信元の限定ではなく保護を有効にします。
