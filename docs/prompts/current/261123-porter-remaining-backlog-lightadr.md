## LADR-003 unicast の性能の対策の進め方と受入の基準

決定者: Tetsuo Honda  
最終更新日: 2026-11-23

### 背景と課題

`unicast` の処理件数が、同じ条件の `tcp` を下回っています (5,000 byte で 0.23 倍)。時間の主因が未計測のため、対策をどこまで、どの順で行うかと、完了を判定する基準を決める必要がありました。

### 得られた事実

- UDP の送信は外側パケットごとに `cplat_socket_sendto()`、受信は 1 周に 1 個の `recvfrom` です (`thread/potr_send_thread.c`、`thread/potr_recv_thread.c`)。`app/cplat` に、複数のパケットを 1 回で送受信する関数はありません。
- 2026-11-21 の測定の比 (`unicast` ÷ `tcp`) は、64 byte で 1.03 と 0.86、1,000 byte で 0.69 と 0.88、5,000 byte で 0.23 と 0.34 です (前が送信の指定なし、後が待ち合わせを指定)。
- 前の案件で、ユーザーは「1 対 1 の比較で数倍の劣化になっていない限りは問題ない」としています。

### 決定

計測で主因を特定し、その結果を示して対策の方式を追加の Q で合意したうえで、同じ案件で実装と確認まで行います。受入の基準は、6 条件のすべてで `unicast` ÷ `tcp` が 0.5 以上、かつ、現在 0.5 以上の条件の比を下げないこと、とします。ただし、待ち合わせを指定した 5,000 byte だけは、「対策の前 (0.34) より下げないこと」とします (LADR-007)。

## LADR-004 SIGSEGV の再現の試験と終了の条件

決定者: Tetsuo Honda  
最終更新日: 2026-11-23

### 背景と課題

`porter-bench` の `p6` の測定で、1 回だけ SIGSEGV が起きました。再現していないため、調査をどの時点で終えるかを決める必要がありました。

### 得られた事実

- 異常終了の後の、通常の 200 回、デバッガーの下の 304 回、valgrind の下の 6 回の実行で、再発していません (対策元の残課題一覧)。
- ユーザーの申告: 異常終了の当時、OS のメモリ不足が発生していました。
- この環境には、`libasan` と `libtsan` のパッケージが導入されていません (`rpm -q` で確認。2026-11-23)。
- 方針の変更の前に、OS のパッケージを一時領域へ展開して行った ASan のビルドの 58 回の実行 (うち 44 回で切断と再接続) で、ASan の報告と異常終了は 0 でした。

### 決定

サニタイザーを使わない通常の構成の、固定した実行ファイルと共有ライブラリで、切断と再接続が 100 回以上起きるまで実行します。異常終了がなければ、実行の条件と回数を記録して、項目を解消 (クローズ) とします。

## LADR-007 unicast の性能の対策の方式

決定者: Tetsuo Honda  
最終更新日: 2026-11-23

### 背景と課題

`unicast` の処理件数の頭打ちの主因を計測で特定した後、どの方式で対策するかを決める必要がありました。

### 得られた事実

- `unicast` の送信スレッドは、DATA パケットを 1 個送出するたびに、ヘルス チェックのスレッドを起こしています (`potr_send_thread.c` の `flush_packed()` の末尾)。1 対 1 の片方向の UDP の送信側だけの処理で、`tcp` にはありません。
- 5,000 byte・送信の指定なしの `unicast` で、送信スレッドは CPU を 1 つ使い切り (約 7 秒の実行で、カーネル 6.1 秒)、スタックの標本 3 回は、3 回ともこの起床の処理の中でした。
- 一時領域の複製でこの起床だけを外すと、`unicast` ÷ `tcp` の比は、5,000 byte・送信の指定なしで 0.23 から 0.62、1,000 byte・送信の指定なしで 0.66 から 1.17、待ち合わせを指定した 5,000 byte で 0.34 から 0.48 になりました (再現の試験と同時に測った参考の値)。
- ヘルス チェックのスレッドは、「最後に PING または DATA を送った時刻 + `health_interval_ms`」まで眠り、目を覚ますたびに期限を計算し直します (`potr_health_thread.c`)。
- 一時領域の複製での一括の送信 (`sendmmsg()`) の実験で、待ち合わせを指定した 5,000 byte の比は、0.44 から 0.49 が、0.81 から 0.97 になりました。送信の指定なしの 5,000 byte では、はっきりした効果は見えませんでした (再現の試験と同時に測った参考の値)。

### 決定

DATA パケットの送出のたびにヘルス チェックのスレッドを起こす処理を、外します。一括の送信 (複数のパケットを 1 回の呼び出しで送る方法) は、この案件では実装せず、実験の結果を付けて残課題一覧に記録し、別の案件で設計します。受入の基準は、待ち合わせを指定した 5,000 byte だけ、「対策の前 (0.34) より下げないこと」とし、ほかの 5 条件は LADR-003 のとおり (0.5 以上、かつ下げない) とします。
