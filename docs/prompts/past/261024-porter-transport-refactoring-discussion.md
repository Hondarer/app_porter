## 現在の実装から分かる分離境界

### BL-002 は接続前処理と共有状態の採用処理を区別する

[potr_connect_thread.c](../../../prod/libsrc/porter/thread/potr_connect_thread.c) は、TCP connect のタイムアウト処理、最初のパケットの読み取り、セッションの新旧比較、送受信者の管理ループと start/stop を持ちます。  
受信者では、読み取りと解析の後に `session_establish_mutex`、`tcp_recv_mutex` の順でロックし、サービス ID と認証の検査、セッション比較と状態更新を行います。  
比較関数を移す場合も、呼び出し元のロック保持条件を維持する必要があります。

接続後のスレッド起動は [potr_connected_threads.c](../../../prod/libsrc/porter/thread/potr_connected_threads.c) がすでに担当しています。  
認証は既存の `thread_recv_authenticate_packet` を再利用しており、新しい認証処理を複製する必要はありません。  
BL-001 で整理した部分起動失敗の回収と start/stop は、この分離でも保持します。

### BL-003 は方式の選択と方式固有の準備を分けられる

[api_open_paths.c](../../../prod/libsrc/porter/api/api_open_paths.c) の `api_open_paths_by_type` は switch で方式を選択しています。  
同じファイルに UDP の各方式、双方向・N:1 と TCP のアドレス解決・listen 準備があり、IPv4 の変換・エラー分類も共用しています。  
方式選択と `api_setup_dest_addr` を入口に残し、UDP・TCP の準備を別の内部ファイルへ分ける案です。  
IPv4 解決など、両方から使う処理は重複させず、最終仕様で配置を確定します。  
成功したソケットのコンテキストへの引き渡しと、途中失敗時の BL-001 の共通解放を保持します。

### BL-004 は監視を同じ受信スレッドの内部処理にできる

[potr_recv_thread.c](../../../prod/libsrc/porter/thread/potr_recv_thread.c) の poll タイムアウト時には、N:1 では `n1_check_health_timeout`、1:1 などでは `check_health_timeout` を呼びます。  
N:1 は `peers_mutex` を保持してパス状態・ピア状態を更新し、ロック解放後に必要な health の起床を行います。  
TCP の受信状態変化では `wake_tcp_interrupt_ping_if_needed` が health の起床と即時 PING の呼び分けを行います。

既存の `thread_recv_session` はセッション状態・通知、`thread_recv_window` は受信ウィンドウ、`thread_recv_dispatch` はパケット処理を担当しています。  
これらを重複実装せず、監視の判断と呼び出し境界を専用の内部ファイルにまとめる案です。  
監視を別スレッドへ移す変更は提案していません。

## 検証と保守の前提

現在の `potrConnectThreadTest` と `potrRecvThreadTest` は主に start/stop と失敗時の回収を検証しています。  
新しい切り出し先には、TCP の待機・EOF・I/O エラー・長さ検査、セッションの新旧、方式別の正常準備と途中失敗、監視無効・期限境界・通知順序を確認する局所テストが必要です。  
既存の `potrConnectedThreadsTest`、`potrPathEventTest`、`potrServiceOpenTest`、`apiContextCleanupTest` などを影響範囲として選びます。

実通信は関連する `porterSendRecvTest` を選び、実行したフィルターと件数を記録します。  
`tcpMultipathTest` は Linux 限定であり、Windows の成功件数には含めません。  
利用できない OS のビルド・実通信を未確認として明記し、Windows の mock テストを Linux の動作確認の代用にしません。

新しいソースは既存の api・thread ディレクトリ内に配置する案です。  
宣言は同じディレクトリの私有ヘッダーへ置き、既存の makefile の走査を利用します。  
テストには元ディレクトリの `INCDIR` を設定し、同じソースを複数の `TEST_SRCS` に重複指定しません。
